# 공릉 밥지도 – 학교 근처 맛집 탐방 웹사이트

카카오 로컬 API, 네이버 블로그 검색 API, 공공데이터(일반음식점 인허가), 날씨 API를 엮어
학교 주변 식당을 추천하는 Next.js 웹사이트입니다.
**API 키가 하나도 없어도 가상의 예시 데이터로 바로 실행됩니다.**

## 1. 실행하기

1. [Node.js](https://nodejs.org) LTS 버전을 설치합니다.
2. 이 폴더에서 터미널을 열고 아래를 실행합니다.

```bash
npm install
npm run dev
```

3. 브라우저에서 http://localhost:3000 을 엽니다.

## 2. 실제 데이터 연결하기

`.env.example` 파일을 복사해 `.env.local`로 이름을 바꾸고 키를 채운 뒤, `npm run dev`를 다시 실행합니다.
키는 연결하고 싶은 것만 넣으면 되고, 빈 값은 그 기능만 꺼집니다.

| 기능 | 필요한 값 | 발급처 |
|---|---|---|
| 주변 식당 목록 | `KAKAO_REST_API_KEY` | developers.kakao.com → 앱 생성 → [카카오맵] 사용 설정 ON |
| 실제 지도 | `NEXT_PUBLIC_KAKAO_JS_KEY` | 같은 앱의 JavaScript 키 + [플랫폼 > Web]에 `http://localhost:3000` 등록 |
| 후기 수 (인기도) | `NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET` | 네이버 검색 API (developers.naver.com 또는 NAVER API HUB) |
| 신상 · 노포 · 폐업 | `data/` 폴더에 CSV | 공공데이터포털 → "일반음식점" 인허가 파일데이터 다운로드 |
| 날씨 반영 | 필요 없음 | Open-Meteo (무료, 키 없음) |

> 공공데이터는 파일(CSV)로 받아 `data/` 폴더에 넣는 방식을 추천합니다. 전국 파일이어도 `PUBLIC_DATA_SGG`(기본 노원구)에 해당하는 가게만 사용합니다.
> 오픈API로 받고 싶다면 활용신청 후 명세에 적힌 요청주소를 `DATA_GO_KR_URL`에 넣으세요.

## 2-1. 폐업한 가게 거르기

**방법 A – 직접 적기 (가장 빠름)**: `data/closed.json`에 가게 이름을 적으면 목록에서 빠집니다.
GitHub 저장소에서 이 파일을 열어 연필(✏️) 버튼으로 수정하고 Commit하면 Vercel이 자동으로 다시 배포합니다.

```json
["부어치킨", "OO식당 공릉점"]
```
이름 일부만 적으면 그 이름이 들어간 가게가 모두 숨겨지고, 지점명까지 적으면 그 지점만 숨겨집니다.

**방법 B – 공공데이터로 자동 거르기**: 구청에 폐업 신고된 가게를 자동으로 뺍니다. (카카오 키 사용 시 정확도가 높음)
1. 공공데이터포털에서 "일반음식점" 인허가 CSV 파일을 내려받습니다.
2. 전국 파일은 너무 크므로 아래 명령으로 노원구만 남깁니다.
   ```bash
   npm run filter-data -- "내려받은파일.csv"
   ```
3. 생성된 `data/restaurants-노원구.csv`를 GitHub의 `data` 폴더에 올립니다.
4. 사이트의 "폐업 제외" 필터가 켜져 있으면 폐업 가게가 빠지고, 신상·노포 필터도 함께 켜집니다.

## 3. 기능

- **반경 / 정렬**: 300m~1.5km, 추천순 · 거리순 · 후기 많은 순
- **음식 종류**: 카카오 카테고리(한식, 일식, 분식…)로 다중 선택
- **신상**: 인허가일 기준 개업 1년 이내 / **노포**: 10년 이상 / **폐업 제외**
- **날씨 반영**: 비·눈이면 가까운 곳 우선, 10°C 이하면 국물 메뉴, 27°C 이상이면 시원한 메뉴에 가산점
- **공강 모드**: (왕복 도보 + 식사 + 대기) 시간이 다음 수업 전에 끝나는 곳만 표시
- **랜덤 뽑기**: 현재 필터를 통과한 가게 중 하나를 추천

## 4. 추천 점수

```
S = w_d·D + w_b·B (+ 날씨 보너스)
D = 1 - 거리/반경                    가까울수록 1
B = log(1+n) / log(1+n_max)          n = 블로그 후기 수
평소 w_d = 0.4, w_b = 0.6 / 비·눈 오는 날 w_d = 0.7, w_b = 0.3
```

도보 시간은 직선거리 × 1.3(골목 우회 보정) ÷ 분당 67m(시속 약 4km)로 계산합니다.
계산 코드는 `lib/score.js`에 있습니다. 상세를 펼치면 가게별 점수 계산식이 표시됩니다.

## 5. 폴더 구조

```

app/api/weather/route.js  서버: 날씨

lib/score.js              필터링과 추천 점수
lib/mock.js               키가 없을 때 쓰는 가상 데이터
components/App.jsx        화면
components/MapView.jsx    카카오맵 (키 없으면 반경 지도)
```

## 6. 주의사항

- API 키는 서버에서만 사용합니다. `NEXT_PUBLIC_` 이 붙은 값만 브라우저에 노출됩니다.
- 카카오 운영정책상 로컬 API 결과는 저장·캐싱하지 않고 매번 실시간으로 호출합니다.
- 카카오 카테고리 검색은 한 번에 최대 45곳까지만 주므로, 범위를 4등분하며 다시 검색해 모두 가져옵니다. 한 번 불러올 때 최대 120회(`KAKAO_MAX_CALLS`)까지 호출합니다.
- 네이버 후기 수는 하루 호출 한도를 지키려고 가까운 100곳(`NAVER_MAX_LOOKUPS`)까지만 조회합니다.
- 블로그 후기 수에는 광고 글이나 같은 이름의 다른 가게가 섞일 수 있어 정확한 인기도는 아닙니다.
- 배포는 GitHub에 올린 뒤 Vercel에서 가져오고, 환경변수를 Vercel 설정에 똑같이 넣으면 됩니다. 이때 카카오 [플랫폼 > Web]에 배포 주소도 등록하세요.
